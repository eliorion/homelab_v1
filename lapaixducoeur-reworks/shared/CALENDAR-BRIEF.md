# Calendar sync brief: same for every site

**Goal.** The association keeps its events in a public **Google Calendar**. A scheduled job runs
`shared/tools/calendar-sync.mjs`, which writes `content/events/gcal-*.json` in each site's own event
schema; then the site rebuilds. Visitors must be able to **subscribe** to the association's events
in their own calendar app.

Read `shared/tools/calendar-sync.mjs` (header and the `SITES` map entry for your site) and test it with
`node shared/tools/calendar-sync.mjs --site <your-site> --ics shared/tools/fixtures/google-calendar-sample.ics`.
The fixture covers a weekly series, a skipped date, a moved date, a UTC event and an all-day event.

## What to add to your site (work only inside your site folder)

1. **Combined feeds.** Generated by `build.mjs`:
   - `dist/calendar.ics` (bilingual or French)
   - `dist/fr/calendrier.ics` and `dist/en/calendar.ics` (one language each)

   Each contains every upcoming event. Requirements:
   - `X-WR-CALNAME`, a `VTIMEZONE` for America/Toronto (or UTC times), and stable `UID`s based on the event file id
   - `URL` pointing to the event page, CRLF line endings, and lines folded at 75 octets
   - Reuse the site's existing per-event .ics code.

   Site 4 already has a feed: keep it and only fill gaps.
2. **"Subscribe / S'abonner" block.** Put it on the events list page and, compactly, on each event page. If the home page has an events section, add a link there too. It offers:
   - **Apple / Outlook desktop:** a `webcal://<host>/fr/calendrier.ics` link, built from `settings` site URL.
   - **Google Calendar:** `https://calendar.google.com/calendar/render?cid=<webcal URL, encoded>`.
   - **Outlook.com:** `https://outlook.live.com/calendar/0/addfromweb?url=<https URL, encoded>&name=<encoded name>`.
   - **Copy link:** a button that copies the https .ics URL, using the site's existing copy-to-clipboard code if it has one.

   Add one line of help text in each language, for example:
   > «Les nouveaux événements apparaîtront automatiquement dans votre agenda.» / "New events will appear in your calendar automatically."
3. **Settings / CMS.**
   - Add optional settings fields `calendar_google_public_url`, the public "web view" link of the Google Calendar. If set, show an extra "Voir dans Google Agenda / View in Google Calendar" link.
   - Add `calendar_ics_source`, the Google iCal address the sync job reads. This is a setting for staff, not shown on the site.
   - Add both to `admin/config.yml` with French hints.
   - In the CMS events collection, add a French `description` (Sveltia shows it), e.g. «Astuce : les événements réguliers (maraudes, collectes) se gèrent plus simplement dans Google Agenda ; ils apparaissent ici automatiquement après la synchronisation. Utilisez ce formulaire pour les événements spéciaux avec photo et texte long.»
4. **Synced events must render well.** Events with `"source": "google-calendar"` may have empty image alt (site 3 has none), an empty ticket URL and no shifts, bring or meeting point. They may also have a `body` with simple line breaks.
   - Make sure templates handle these gracefully.
   - Optionally show a tiny "Synchronisé depuis Google Agenda" note for staff? **No.** Show nothing to visitors.
   - All-day events have start `T00:00` and end `T23:59`. Display them as "Toute la journée / All day" instead of times, in the page, the list and the .ics (use `DTSTART;VALUE=DATE`).
5. **README.** Add a short "Calendar sync" section: how staff use Google Calendar (the conventions are in `shared/EDITOR-GUIDE.md`), the command, and where the feeds are.

## Verify

1. Sync the fixture into your site.
2. `node build.mjs`.
3. Run your site's own verifier (it lives in the site folder: `scripts/`, `tests/` or `tools/`; site 5 had none committed, so do a Playwright pass on events pages in both languages at 375 and 1440 px).

It must show no console errors, no 404s, unique titles and descriptions, and valid structured data.

Check that the .ics files parse: for example, count `BEGIN:VEVENT`, and check that the CRLF line endings and the 75-octet line folding are correct.

Look at a screenshot of the events page with the subscribe block on mobile and desktop.

**Then delete the `gcal-*.json` fixture files and rebuild**, so the demo keeps only its own sample events. Do not commit and do not touch other folders. Report briefly.
